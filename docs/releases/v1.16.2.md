# v1.16.2

> Not published. Release CI rejected the committed formatting under the current stable rustfmt; v1.16.3 fixed that but was itself superseded by [v1.16.4](v1.16.4.md).

## English

### Changes

- Fix a Linux-only quota-refresh lock-safety defect: a holder whose lock directory had been reaped could identify a same-named replacement lock as its own and refresh or delete it. The holder now keeps the directory handle open for the lock lifetime, so the inode/file ID cannot be reused, and ownership requires both the held handle and the current path to match. The official client's rmdir/rename protocol is unchanged.
- Make the Windows quota-fill tests independent of file-IO speed. Tests now synchronize on per-account query gates and applied-result barriers instead of fixed 100/300 ms waits; production behavior is unchanged.
- Classify `fs2` lock contention through the library's official `lock_contended_error()` instead of comparing only `ErrorKind::WouldBlock`, which is not reliable for `ERROR_LOCK_VIOLATION` on Windows.
- Include all quota-collection improvements from the unpublished v1.16.0/v1.16.1 drafts: cross-process collection reservations and coalescing, bounded concurrency, adaptive per-account scheduling, reset-expiry refreshes, typed `Retry-After` deadlines, read-only `subswap status --json`, and bounded request metrics.

### Verification and limits

macOS ARM64 workspace check, strict Clippy (`-D warnings`), formatting, 468 tests and the locked release build pass without compiler or lint warnings. The previously failing Windows tests passed 60 consecutive local runs. The Linux lock defect and its regression test were reproduced and verified on Ubuntu 22.04; Windows was compile-checked locally because no Windows runtime is available, so CI remains the authoritative Windows/runtime check. These checks do not establish a vendor's guaranteed request allowance or instantaneous reset propagation.

Apple clients continue to read snapshots; this release adds no direct vendor-request path from the GUI or widgets. Already invalid credentials are not repaired by polling more often.

### Upgrade

```sh
brew upgrade subswap
```

Restart an independently managed daemon after upgrading.

## 简体中文

> 未发布。发布 CI 用当前稳定版 rustfmt 检查提交格式未通过；v1.16.3 修复了格式，但随后又被 [v1.16.4](v1.16.4.md) 取代。

### 更新内容

- 修复 Linux 专属的额度刷新锁安全问题：锁目录被回收后，旧持有者可能把同名重建的新锁误认成自己的锁，从而续租或删除它。现在持有者在整个持锁期间保持目录句柄打开，使 inode / file ID 无法被复用；判断归属时必须同时满足持有句柄与当前路径身份一致。官方客户端的 rmdir/rename 协议不变。
- 让 Windows 额度填充测试不再依赖文件 IO 速度：改用按账号查询闸门和结果落地屏障，不再用固定 100/300 ms 等待；生产行为不变。
- `fs2` 锁竞争改用库官方 `lock_contended_error()` 判断，不再只比较 `ErrorKind::WouldBlock`；Windows 的 `ERROR_LOCK_VIOLATION` 不能靠该 kind 稳定识别。
- 包含此前未发布的 v1.16.0 / v1.16.1 草稿中的全部额度采集优化：跨进程请求预约与并发合并、有界并发、按账号自适应调度、额度窗口重置刷新、`Retry-After` 期限、只读 `subswap status --json` 以及有界请求统计。

### 验证与限制

macOS ARM64 全 workspace 检查、严格 Clippy（`-D warnings`）、格式检查、468 项测试和 locked release 构建通过，没有编译或 lint 警告。此前失败的 Windows 测试在本地连续运行 60 次全部通过。Linux 锁缺陷及其回归测试已在 Ubuntu 22.04 复现并验证；本机没有 Windows 运行环境，只做了编译检查，因此 Windows/运行时验证仍以 CI 为准。这些检查不代表厂商承诺的请求额度，也不保证上游在倒计时归零时立即更新数据。

苹果客户端继续读取快照；本版不从 GUI 或小组件新增直接请求厂商的路径。已经失效的凭证不会因为更频繁轮询而恢复。
