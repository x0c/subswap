# v1.16.5

## English

### Changes

- Add `subswap status --json --no-metrics` for GUI and widget consumers that poll frequently. It omits only the diagnostic `request_metrics` block, leaving every account, quota, freshness and daemon field unchanged, and keeps the default full output for diagnostics. The full payload had grown past 160 KiB, so pollers that drained it slowly or incorrectly paid a large per-refresh cost.
- Document the pipe-capacity contract for snapshot consumers: a child that writes more than 64 KiB into a pipe while the parent waits for exit deadlocks. The companion Subswap Apple client now redirects CLI output to temporary files with a hard timeout; this release provides the smaller polled payload it prefers, with a fallback for older binaries.

### Verification and limits

macOS ARM64 workspace check, strict Clippy (`-D warnings`), `cargo fmt --all --check`, the read-only status regression suite and the locked release build pass. A real `status --json --no-metrics` run was compared against the full output and against the installed client, which now refreshes on its own timer.

### Upgrade

```sh
brew upgrade subswap
```

Restart an independently managed daemon after upgrading.

## 简体中文

### 更新内容

- 新增 `subswap status --json --no-metrics`，面向高频轮询的 GUI 与小组件消费者。它只省略诊断用的 `request_metrics`，账号、额度、新鲜度与 daemon 字段完全不变；默认完整输出继续服务诊断场景。完整载荷已增长到 160 KiB 以上，读取方式不当或较慢的轮询方每次刷新都要付出很高代价。
- 明确快照消费者的管道容量约束：子进程写管道超过 64 KiB、父进程却在等退出时会双向死锁。配套的 Subswap Apple 客户端已改为把 CLI 输出重定向到临时文件并加硬超时；本版本提供它优先请求的精简载荷，并保留旧二进制回退路径。

### 验证与限制

macOS ARM64 workspace 检查、严格 Clippy（`-D warnings`）、`cargo fmt --all --check`、只读状态回归测试与加锁 release 构建均通过。已用真实 `status --json --no-metrics` 与完整输出对比，并确认已安装客户端按自身定时器恢复刷新。

### 升级

```sh
brew upgrade subswap
```

独立管理的 daemon 升级后需重启。
