# v1.16.3

> Superseded by [v1.16.4](v1.16.4.md). Release CI passed, but a later daemon scheduling audit found empty successful readings still used the request floor.

## English

### Changes

- Format the Windows quota-fill tests with the current stable rustfmt, which the release CI requires. This is a formatting-only change; behavior is identical to v1.16.2.
- Fix a Linux-only quota-refresh lock-safety defect: a holder whose lock directory had been reaped could identify a same-named replacement lock as its own and refresh or delete it. The holder now keeps the directory handle open for the lock lifetime, so the inode/file ID cannot be reused, and ownership requires both the held handle and the current path to match.
- Make the Windows quota-fill tests independent of file-IO speed by synchronizing on per-account query gates and applied-result barriers instead of fixed waits.
- Classify `fs2` lock contention through the library's official `lock_contended_error()`, which is reliable for `ERROR_LOCK_VIOLATION` on Windows.
- Include all quota-collection improvements from the unpublished v1.16.0–v1.16.2 drafts: cross-process collection reservations and coalescing, bounded concurrency, adaptive per-account scheduling, reset-expiry refreshes, typed `Retry-After` deadlines, read-only `subswap status --json`, and bounded request metrics.

### Verification and limits

macOS ARM64 workspace check, strict Clippy (`-D warnings`), `cargo fmt --all --check` with stable rustfmt 1.10, 468 tests and the locked release build pass without compiler or lint warnings. The previously failing Windows tests passed 60 consecutive local runs. The Linux lock defect and its regression test were reproduced and verified on Ubuntu 22.04; Windows was compile-checked locally because no Windows runtime is available, so CI remains the authoritative Windows/runtime check.

Apple clients continue to read snapshots; this release adds no direct vendor-request path from the GUI or widgets. These checks do not establish a vendor's guaranteed request allowance or instantaneous reset propagation.

### Upgrade

```sh
brew upgrade subswap
```

Restart an independently managed daemon after upgrading.

## 简体中文

> 已由 [v1.16.4](v1.16.4.md) 取代。发布 CI 已通过，但随后 daemon 调度审计发现空成功读数仍按请求地板重采。

### 更新内容

- 按发布 CI 要求的当前稳定版 rustfmt 重新格式化 Windows 额度填充测试。仅格式变化，行为与 v1.16.2 相同。
- 修复 Linux 专属的额度刷新锁安全问题：锁目录被回收后，旧持有者可能把同名重建的新锁误认成自己的锁，从而续租或删除它。现在持有者在整个持锁期间保持目录句柄打开，使 inode / file ID 无法被复用；判断归属时必须同时满足持有句柄与当前路径身份一致。
- 让 Windows 额度填充测试不再依赖文件 IO 速度：改用按账号查询闸门和结果落地屏障，不再用固定等待。
- `fs2` 锁竞争改用库官方 `lock_contended_error()` 判断；Windows 的 `ERROR_LOCK_VIOLATION` 不能靠 `ErrorKind::WouldBlock` 稳定识别。
- 包含此前未发布的 v1.16.0–v1.16.2 草稿中的全部额度采集优化：跨进程请求预约与并发合并、有界并发、按账号自适应调度、额度窗口重置刷新、`Retry-After` 期限、只读 `subswap status --json` 以及有界请求统计。

### 验证与限制

macOS ARM64 全 workspace 检查、严格 Clippy（`-D warnings`）、稳定版 rustfmt 1.10 的 `cargo fmt --all --check`、468 项测试和 locked release 构建通过，没有编译或 lint 警告。此前失败的 Windows 测试在本地连续运行 60 次全部通过。Linux 锁缺陷及其回归测试已在 Ubuntu 22.04 复现并验证；本机没有 Windows 运行环境，只做了编译检查，因此 Windows/运行时验证仍以 CI 为准。

苹果客户端继续读取快照；本版不从 GUI 或小组件新增直接请求厂商的路径。这些检查不代表厂商承诺的请求额度，也不保证上游在倒计时归零时立即更新数据。
