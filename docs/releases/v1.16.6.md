# v1.16.6

## English

### Changes

- Order quota windows by their real duration in the default quota table and the human-readable `subswap status` view. A provider's new 20-day window now appears between 7 days and a month instead of after the monthly window; non-time quota pools remain after timed windows.
- Preserve non-standard window lengths as duration tokens such as `20d`, `3h`, `90m` and `45s` in cached quotas and JSON snapshots. Codex and Kimi retain upstream durations, and quota-cache expiry uses the actual window length. Existing standard tokens (`five_hour`, `seven_day`, `month`) remain unchanged.

### Verification and limits

macOS ARM64 workspace check, formatting, strict Clippy (`-D warnings`), all 474 Rust tests, debug build and locked release build pass without compiler or lint warnings. The installer regression suite also passes with PowerShell 7.6.6. The release binary was run against synthetic cached quotas: `45s` → `90m` → `3h` → `five_hour` → `seven_day` → `20d` → `month` → non-time pools; JSON retains each duration token, `--no-metrics` preserves account data, and reads leave fixture files unchanged. The [release workflow](https://github.com/x0c/subswap/actions/runs/40248378004) passed three-platform CI, all five release builds and the exact Windows draft installer check. All five public archives and checksums were downloaded anonymously and verified. The published Mac ARM64 CLI/daemon were installed with matching hashes; the real default entry, daemon and duration-token smoke checks passed. Homebrew updated automatically. Two third-party Zig-setup action runtime deprecation notices are assessed in the [operations guide](https://github.com/x0c/subswap/blob/main/docs/OPERATIONS_GUIDE.md#retained-third-party-workflow-diagnostics); there are no compiler/lint warnings.

Snapshot consumers should accept duration tokens in the `window` field and parse their length for sorting and labels. Windows packages contain the CLI only; macOS and Linux packages also include the daemon.

### Upgrade

```sh
brew upgrade subswap
```

Restart an independently managed daemon after upgrading. Existing accounts and configuration require no migration.

## 简体中文

### 更新内容

- 默认额度表和 `subswap status` 人读视图按窗口的实际时长排序。厂商新增的 20 天窗口现在排在 7 天与月度窗口之间，不再排到月度窗口之后；非时间额度池仍放在时间窗口之后。
- 缓存额度和 JSON 快照使用 `20d`、`3h`、`90m`、`45s` 等时长 token 保留非标准窗口长度。Codex 和 Kimi 保留上游提供的时长，额度缓存过期计算使用真实窗口长度。现有标准 token（`five_hour`、`seven_day`、`month`）保持不变。

### 验证与限制

macOS ARM64 workspace 检查、格式检查、严格 Clippy（`-D warnings`）、全部 474 项 Rust 测试、debug 构建及 locked release 构建通过，没有编译或 lint 警告。安装器回归套件也已在 PowerShell 7.6.6 下通过。使用合成缓存额度运行 release 二进制，顺序为 `45s` → `90m` → `3h` → `five_hour` → `seven_day` → `20d` → `month` → 非时间池；JSON 保留各时长 token，`--no-metrics` 保留账号数据，读取前后夹具文件不变。[发布流程](https://github.com/x0c/subswap/actions/runs/40248378004) 已通过三平台 CI、全部五个发布构建及本次版本的 Windows 草稿安装验证。五个公开压缩包及校验和均已匿名下载并核对。公开的 Mac ARM64 CLI/daemon 已安装，哈希一致；真实默认入口、daemon 和时长 token 冒烟验证通过。Homebrew 已自动更新。两条第三方 Zig 安装 Action 的运行时弃用提示及其评估见[运行指南](https://github.com/x0c/subswap/blob/main/docs/OPERATIONS_GUIDE.md#retained-third-party-workflow-diagnostics)；没有编译或 lint 警告。

快照消费者应接受 `window` 字段中的时长 token，并解析其长度用于排序和标签。Windows 安装包只包含 CLI；macOS 和 Linux 安装包同时包含 daemon。

### 升级

```sh
brew upgrade subswap
```

升级后重启自行管理的 daemon。现有账号和配置无需迁移。
