# v1.16.1

> Not published. Linux lock-safety and Windows test-timing defects found by the release CI are fixed in [v1.16.2](v1.16.2.md).

## English

### Changes

- Fix a Windows-only unused-import error found by the strict release checks. This release includes the complete quota-collection improvements below; the earlier v1.16.0 draft was not published.
- Share quota collection across CLI and daemon processes: durable reservations, duplicate-request coalescing, bounded concurrency and atomic per-account cache merging.
- Reduce routine background collection to about three minutes for active accounts and 15 minutes for parked accounts, with positive jitter and bounded candidate checks near the switching threshold. Idle collection remains slower.
- Refresh affected accounts after any known quota-window countdown expires, including healthy and parked accounts. The default post-reset delay is two seconds; minimum request intervals and server cooldowns still take precedence. A timer never fabricates a full balance.
- Preserve HTTP `Retry-After` deadlines across providers, including deadlines longer than the generic failure-backoff cap. Keep Claude's stricter polling; renew an expired active credential only under the verified official refresh-lock protocol (Claude Code 2.1.310 or newer), without starting a client session or interfering with an existing lock holder.
- Add read-only `subswap status --json` for Apple apps/widgets and other consumers. Reads preserve original observation timestamps, report stale/error states, redact secret-like labels and do not fetch quota, start a daemon or create application state directories.
- Export bounded request metrics, including per-provider/account recent-hour totals. Direct HTTP and native RPC calls are counted separately; official clients' internal HTTP traffic is not observable.
- Invalidate removed accounts' quota state without resurrecting old in-flight readings or discarding existing cooldown deadlines.

### Verification and limits

The macOS ARM64 workspace check, strict Clippy, 466 tests, debug build and locked release build passed without compiler/lint warnings. Real CLI/daemon processes against an isolated local HTTP fixture confirmed one post-reset request, no writes or additional requests across eight status reads, and one HTTP request shared by two concurrent CLI invocations. These fixtures do not establish a vendor's guaranteed request allowance or instantaneous upstream reset propagation.

Windows has no background daemon. Apple clients continue reading snapshots; this release does not add direct vendor requests or change their graphical interface. Already invalid credentials are not repaired by polling more often. Official-lock credential adoption was checked locally without forcing a real token rotation; natural-expiry renewal on a live account remains unobserved.

### Upgrade

```sh
brew upgrade subswap
```

Restart an independently managed daemon after upgrading. macOS automatic startup still requires `SUBSWAP_AUTO_DAEMON=1`; read-only status does not enable it.

## 简体中文

> 未发布。发布 CI 发现的 Linux 锁安全和 Windows 测试时序缺陷已在 [v1.16.2](v1.16.2.md) 修复。

### 更新内容

- 修复严格发布检查发现的 Windows 专属未使用导入错误。本版包含下列全部额度采集优化；此前的 v1.16.0 草稿未公开发布。
- CLI 与 daemon 共用额度采集协调器：持久请求预约、并发查询合并、有界并发，以及按账号原子合并缓存。
- 活跃账号通常约三分钟采集一次，备用账号约十五分钟一次；加入正向错峰，并在接近切换阈值时有界确认候选。空闲时仍保持更低频率。
- 任何已知额度窗口的倒计时结束后，都会安排刷新受影响账号，包括健康账号和备用账号。默认延迟两秒；最小请求间隔和服务器冷却期限仍然优先，不会因为计时器到点就伪造满额。
- 各 Provider 保留 HTTP `Retry-After` 期限，即使它超过通用失败退避上限；Claude 继续采用更严格的采样。活跃凭证过期时，只在已核实的官方刷新锁协议下续期（Claude Code 2.1.310 或更新版本），不启动客户端会话，也不干扰现有持锁者。
- 新增供苹果客户端、小组件及其他消费者使用的只读 `subswap status --json`。保留真实观测时间，区分旧数据与错误，隐藏疑似密钥标签；读取不会查额度、启动 daemon 或创建应用状态目录。
- 新增有界请求统计，包括按厂商和账号划分的最近一小时计数。直接 HTTP 与原生 RPC 分开统计；无法观测官方客户端内部的 HTTP 请求。
- 删除账号时同步使额度状态失效，不再复活旧的在途读数，也不会丢掉已有冷却期限。

### 验证与限制

macOS ARM64 全 workspace 检查、严格 Clippy、466 项测试、debug 构建及 locked release 构建通过，没有编译或 lint 警告。真实 CLI/daemon 进程配合隔离的本地 HTTP 夹具验证：重置后仅查询一次；连续八次只读状态查询没有写入或增加网络请求；两个并发 CLI 共用一次 HTTP 查询。这些夹具不代表厂商承诺的请求额度，也不保证上游在倒计时归零时立即更新数据。

Windows 不提供后台 daemon。苹果客户端继续读取快照；本版不新增直接请求厂商的路径，也不修改图形界面。已经失效的凭证不会因为更频繁轮询而恢复。本机已验证官方锁内采用现有有效凭证，没有强制轮换真实令牌；真实账号自然过期后的续期尚未观测。

### 升级

```sh
brew upgrade subswap
```

升级后重启自行管理的 daemon。macOS 自动启动仍需 `SUBSWAP_AUTO_DAEMON=1`；只读状态查询不会将其开启。
